비용 구조

비싼 것은 판단이 아니라 분량입니다

과금은 대부분 출력 토큰에서 발생합니다. 코드를 새로 쓰는 일은 출력이 길고, 읽고 지적하는 일은 출력이 짧습니다. 그래서 같은 작업이라도 누가 맡느냐에 따라 청구서가 달라집니다.

  • 생성은 출력이 깁니다

    파일 하나를 새로 쓰면 수천 토큰이 나갑니다. 리팩터링도, 테스트 작성도 같습니다. 돈은 여기서 빠집니다.

  • 검수는 출력이 짧습니다

    읽고 "여기가 틀렸다"고 답하는 일은 출력이 몇 줄입니다. 입력이 길어도 출력 단가에 비하면 부담이 작습니다.

  • 그래서 나누면 내려갑니다

    분량이 나가는 일은 값싼 쪽으로, 판단만 상위 모델로. 로컬로 내리면 그쪽 토큰 비용은 0원이 됩니다.

  1. 상위 모델 $25
  2. 값싼 원격 모델 $5

그런데 왜 다들 안 내리는가

값싼 쪽을 혼자 두면, 뭘 했는지 알 방법이 없기 때문입니다

아래는 에이전트를 여럿 붙여 55일을 굴리면서 실제로 겪은 일들입니다. 값이 싼 쪽에 맡길수록 더 자주 납니다.

  • 에이전트 A가 고쳐 놓은 파일을, 에이전트 B가 통째로 예전 버전으로 되돌려 놨습니다.
  • 두 에이전트가 같은 함수를 각자 다르게 고쳐 놓고, 둘 다 "완료했습니다"라고 보고했습니다.
  • 어제까지 되던 기능이 오늘 안 됩니다. 누가 언제 무엇을 건드렸는지 남아 있는 기록이 없습니다.
  • 새 창을 열 때마다 에이전트가 다른 사람처럼 굴어서, 매번 처음부터 다시 설명하고 있습니다.
  • 한 에이전트가 배포한 걸 다른 에이전트가 또 배포해서, 롤백 순서가 꼬였습니다.
  • 응답이 끊긴 에이전트의 작업을 이어받아야 하는데, 어디까지 했는지 알 방법이 없습니다.

이 상황의 비용은 날아간 코드가 아닙니다. "지금 이 상태가 맞는 상태인가"를 사람이 매번 다시 확인해야 하는 시간입니다. 그래서 대부분 값싼 쪽에 맡기는 걸 포기하고 비싼 모델로 전부 처리합니다. 안 믿기느니 돈을 더 내는 쪽을 고르는 겁니다. 아래 규율 9가지는 정확히 그 지점을 겨냥합니다. 뭘 했고 뭘 안 했는지, 어디를 건드렸는지가 남으면 값싼 쪽에도 일을 맡길 수 있게 됩니다.

왜 생기는가

모델이 나빠서가 아니라, 셋이 없어서 생깁니다

에이전트는 각자 자기 작업만 봅니다. 옆에서 누가 무엇을 하는지 볼 방법을 주지 않으면, 성실한 에이전트일수록 더 크게 덮어씁니다.

  • 소유권이 없습니다

    모든 에이전트가 모든 파일을 쓸 수 있는 상태입니다. 경계가 없으니 충돌은 사고가 아니라 시간문제입니다.

  • 순서가 없습니다

    시작을 선언하지 않고 바로 손을 댑니다. 둘이 같은 지점에 동시에 들어간 뒤에야 문제가 드러납니다.

  • 기억이 없습니다

    대화 창이 끊기면 맥락이 사라집니다. 다음 에이전트는 남은 코드만 보고 나머지를 추측으로 채웁니다.

규율 9가지

값싼 모델을 실전에 투입할 수 있게 만드는 장치 9가지

싼 쪽에 일을 맡길 때 필요한 건 더 똑똑한 모델이 아니라, 뭘 했는지 남기게 만드는 장치입니다. 미검증 항목을 비우면 완료 보고가 거부되고, 담당 영역 밖은 커밋이 막히고, 되돌리기 어려운 곳은 사람 승인 없이 못 넘어갑니다. 제목은 여기서 전부 공개합니다. 감출 이유가 없습니다. 어려운 건 제목을 아는 게 아니라 매일 지키게 만드는 절차입니다.

  1. 규율 01

    역할 고정 분리

    에이전트마다 담당 영역과 등급을 고정합니다. 분량을 쓰는 손발과 판단을 하는 머리를 섞지 않습니다.

  2. 규율 02

    파일 소유권 분리 + 인터페이스 계약

    서로 만지는 파일을 나누고, 정해진 접점으로만 연결합니다. 경계를 넘는 수정은 계약을 고치는 일이 됩니다.

  3. 규율 03

    작업 시작 선언 의무

    코드를 건드리기 전에 무엇을 할지 먼저 남깁니다. 이 규율만 코드로 구현한 것이 무료 도구 agentlock입니다.

  4. 규율 04

    단일 배포자 원칙

    배포는 한 명만 합니다. 교차 배포를 금지하면 롤백 순서가 꼬이지 않습니다.

  5. 규율 05

    부재 시 승계 프로토콜

    상대가 응답하지 않을 때 무엇을 어떤 순서로 읽고 이어받는지 정해 둡니다. 판단이 아니라 절차로 처리합니다.

  6. 규율 06

    정체성 고정 프롬프트

    등급에 맞는 자아를 고정합니다. 손발에게는 혼자 판단하지 말라고, 머리에게는 분량 작업을 직접 하지 말라고 박아 둡니다.

  7. 규율 07

    완료 보고에 검증 증거 의무

    무엇을 검증했고 무엇을 못 했는지 함께 적습니다. 미검증 항목을 비워 두면 완료 보고 자체가 거부됩니다.

  8. 규율 08

    승인 게이트

    배포, 금액, DB 구조 변경은 사람 승인을 거칩니다. 값싼 쪽이 위험 구역에 혼자 들어가지 못하게 막는 자리입니다.

  9. 규율 09

    append-only 원장

    한 일은 해시로 엮인 기록에 쌓기만 합니다. 한 줄만 고치거나 지워도 몇 번째 줄이 훼손됐는지 잡힙니다.

이 9가지가 서 있지 않으면 값싼 쪽에 일을 맡길 수 없습니다. 뭘 했는지, 뭘 안 했는지, 어디를 건드렸는지 모르는 결과물은 결국 사람이 처음부터 다시 봐야 하고, 그러면 아낀 돈보다 든 시간이 큽니다. 각 규율의 실제 문서, 에이전트별 정체성 프롬프트 템플릿, 인수인계 양식, 충돌 대응 절차는 협업 운영 키트에 들어 있습니다. 같은 9가지를 사람이 지키는 대신 도구가 강제하게 만든 것은 agentlock pro입니다.

역할 분리 세팅

손발과 머리를 나누는 부분이 명령으로 들어 있습니다

아래는 최근에 들어간 기능입니다. 실제로 동작하는 것만 적었습니다. 직접 구조를 짜지 않으셔도 되게, 나누는 지점을 미리 만들어 두었습니다.

  • setup --preset 4

    한 번에 나눠서 세팅

    손발(로컬)과 머리(상위 모델)로 역할을 갈라 한 번에 세팅합니다. 담당 영역, 배포 담당, 승인 지점, git 훅, 등급별 정체성 프롬프트까지 이 명령에서 만들어집니다.

  • env

    로컬 런타임 점검

  • cost

    절감액 계산

로컬 모델이 코드를 제대로 쓰나요?

상위 모델만 못합니다. 이건 분명히 말씀드립니다. 같은 요구사항을 주면 놓치는 조건이 더 많고, 엉뚱한 파일을 건드리는 빈도도 높습니다.

그래서 검수를 붙이는 겁니다. 손발이 쓴 코드를 머리가 읽고 되돌려 보내는 구조라야 결과를 쓸 수 있습니다. 검수 없이 로컬만 쓰시는 건 권하지 않습니다. 그렇게 하면 아낀 돈보다 나중에 원인을 찾는 시간이 더 듭니다.

바꿔 말하면 이 도구가 파는 것은 "값싼 모델이 잘한다"가 아니라 "값싼 모델의 결과를 확인 가능하게 만든다"입니다. 미검증 항목을 비우면 완료 보고가 거부되고, 담당 영역 밖 파일은 커밋이 막히고, 한 일은 해시로 엮인 기록에 남습니다.

장비가 어느 정도여야 하나요?

메모리가 기준입니다. 16GB는 빠듯합니다. 작은 모델은 돌아가지만 맡길 수 있는 작업 폭이 좁습니다. 32GB부터 쓸 만해지고, 64GB 이상이면 생성 작업 대부분을 로컬로 내리실 수 있습니다.

본인 장비가 어디에 해당하는지는 env 명령으로 확인하실 수 있습니다. Ollama, LM Studio, llama.cpp, vLLM 중 무엇이 떠 있는지 감지하고, 메모리를 보고 감당 가능한 모델 규모를 알려줍니다.

장비가 안 되시면 로컬 대신 값싼 원격 모델을 쓰시면 됩니다. 절감폭은 줄지만 장비 조건이 없습니다.

로컬 말고 값싼 원격 모델을 써도 되나요?

됩니다. 구조는 같습니다. 생성을 아래로 내리고 검수를 위에 남기는 방식이라, 아래가 로컬이든 값싼 원격이든 규율은 그대로 적용됩니다.

다만 0원은 아닙니다. 출력 100만 토큰당 $25 대 $5, 5분의 1 수준으로 줄어듭니다. 월 30만원 · 생성 비중 80%인 경우로 계산하면 로컬은 월 6만원, 값싼 원격은 월 10.8만원이 됩니다. 계산기에서 "값싼 원격 모델"을 고르시면 본인 수치로 확인하실 수 있습니다.

정말 이만큼 줄어드나요?

생성 비중에 따라 달라집니다. 계산기는 다음을 가정합니다. 생성 비중만큼의 금액이 내리는 대상으로 옮겨가고 나머지는 상위 모델에 그대로 남는다, 로컬은 토큰 비용 0원이다, 값싼 원격은 5분의 1이다, 회수 기간은 하루 절감액이 일정하다고 보고 나눈 값이다.

기본값 80%에서는 5분의 1이 됩니다. 생성 비중이 90%인 팀이 전부 로컬로 내리면 10분의 1까지 내려갑니다. 반대로 이미 검수와 설계 위주로 쓰고 계셔서 생성 비중이 30%라면 절감폭도 그만큼 작습니다.

계산에 안 들어간 것도 밝혀 둡니다. 전기요금, 장비 구입비, 생성 품질이 떨어져 재작업할 때 드는 시간은 넣지 않았습니다. 그래서 숫자를 믿어달라고 말씀드리지 않고, 계산기에 본인 수치를 넣어 보시라고 말씀드립니다.

다만 저장소 구조는 팀마다 다릅니다. 키트의 양식과 절차는 팀 구조에 맞게 고쳐 쓰시는 것을 전제로 만들었고, 프로판은 setup 단계에서 담당 영역·배포 담당·승인 지점을 직접 지정하시게 되어 있습니다. 구조가 달라도 그 지정만 팀에 맞게 하시면 됩니다.

무료판이랑 프로판 중 뭘 사야 하나요?

먼저 무료판을 하루 돌려보시고 정하셔도 됩니다. 무료판은 규율 9가지 중 1가지(작업 시작 선언)만 코드입니다. 나머지 8가지는 사람이 기억해서 지켜야 합니다.

프로판은 9가지 전부가 코드입니다. 남의 담당 영역 파일은 잠그는 것도 커밋하는 것도 막히고, 완료 보고에서 "검증하지 못한 것" 칸을 비우면 명령이 거부되고, 배포는 지정된 한 명이 사람 승인을 받아야 실행됩니다. 그 승인은 한 번 쓰면 소진됩니다. 지키는지 사람이 확인할 필요가 없어집니다.

기준은 이렇게 잡으시면 됩니다. 혼자 에이전트 하나를 쓰신다면 무료판으로 충분합니다. 에이전트를 둘 이상 동시에 붙이시거나, 사람 동료와 같은 저장소를 쓰신다면 프로판 쪽이 맞습니다.

프로판 안에서 어느 등급을 사셔야 하는지는 아래 “저는 어떤 등급을 사야 하나요” 항목에 정리해 두었습니다.
